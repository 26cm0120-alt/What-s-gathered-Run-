# ワギャラン 開発ドキュメント要約

担当・ゲームルール・開発順・確認待ちの項目をまとめた[開発資料クイックガイド](00_開発資料クイックガイド.md)を追加しました。まずこのガイドを読み、細かな条件は以下の正式文書で確認してください。

ファミコン時代の Wizardry・女神転生を思わせる、SwiftUI製の3D迷宮探索ゲームです。このページは各文書の要点と、現在のルールを短くまとめた入口です。細かな条件やマップ定義はリンク先の正式文書を参照してください。

## ゲームの要点

- **遊び方:** チュートリアル、試練の迷宮、ランダムステージから選びます。上フリックで前進、左右で旋回、下で180度反転します。
- **目的:** 迷宮を探索し、イベントを越えて鍵を手に入れ、ゴールを目指します。ランダムステージでは剣で強化し、敵との戦闘も行います。
- **探索表示:** 3D迷宮はテーマに合わせて描画します。探索マップには発見した範囲だけを表示し、鍵・剣・トラップはドット絵、現在地は青いドラゴンで示します。
- **戦闘:** 敵マスに入ると画面内でターン制戦闘を行います。スライムとスケルトンは剣なしでも倒せます。ガーゴイルは剣なしでは攻撃が通らず、反撃でHPが0になると敗北します。
- **ランダム生成:** seedから通路、イベント、敵、迷宮テーマを決めます。同じseedは同じマップを再現します。500 seedの構造・到達可能性と別プロセス間256 seedの再現性を自動検証済みです。
- **演出:** 敵の遭遇・撃破セリフは順番に表示します。鍵・剣の取得演出中は移動を止めます。戦闘BGMの再生に失敗した場合は探索BGMへ切り替えます。
- **音声処理:** AVAudioSessionの有効化とAVAudioPlayerの準備・再生・停止を共通の直列キューに集約し、しりとり効果音のプレイヤーを再利用します。Xcode 26.3のSimulator向けビルドとiPhone 16e Simulator起動を確認済みです。iPhone SE実機でもしりとりBGMの継続再生を確認し、提示ログにAVAudioSession警告はありません。連続効果音を含む操作時の確認は未実施です。
- **主な追加機能:** 初回からの計時・ベストタイム更新と試練/ランダム別TOP100、ガーゴイル出現、8方向宝箱、ピンチ拡大、戦闘アクション差分、スケルトンドロップ、触覚反応。TOP100への登録はクリア画面で名前を入力して記録を押します。操作確認状況は進捗記録を参照してください。
- **フォント:** MaruMonicaを同梱しています。配布条件は[MaruMonica利用条件](MaruMonica利用条件.md)を参照してください。

## BGM・効果音のアプリ内音量

音量値は音源ごとのアプリ設定です。iPhone本体の音量は別に調整できます。音声セッションは端末の消音設定に従います。

| 音源 | アプリ内音量 | 対象・音源例 |
|---|---:|---|
| タイトルBGM | 50% | `タイトルBGM.m4a` |
| 探索BGM | 50% | 固定面は `探索BGM.m4a`、ランダム4テーマは各専用曲 |
| 通常戦闘BGM | 30% | スライム・スケルトンなどとの戦闘 |
| ガーゴイル戦闘BGM | 30% | ガーゴイルとの戦闘 |
| しりとり画面BGM | 50% | 対局・敗北などのBGM |
| 効果音 | 50% | 移動、攻撃、取得、扉、クリアなど |

ランダムステージのテーマ別音源は、[ゲーム仕様書の音源対応表](02_ゲーム仕様書.md#現行仕様の確認メモ2026-10-21)に記載しています。

戦闘効果音の現行割り当ては、プレイヤー攻撃が `中パンチ.mp3`、スケルトン反撃が `刀で斬る2.mp3`、ガーゴイル反撃が `刀で斬る3.mp3`、スライム反撃が `刀で斬る4.mp3` です。ドラゴン専用の反撃音はありません。配置名と拡張子は[ゲーム仕様書の音源対応表](02_ゲーム仕様書.md#現行仕様の確認メモ2026-10-21)を参照してください。

## 情報の優先順位

開発規約では **仕様書 → UI・画面資料 → 設計 → 現在の正式コード → AIの提案** の順に判断します。資料同士が食い違う場合は、優先順位を独断で決めず、チームで確認して原本を更新します。進捗記録は「何を確認済みか」を示します。ビルド成功だけで、操作や実機確認まで済んだとは扱いません。

## 開発の流れ

1. 規約と関係する仕様を読む。
2. 変更範囲と完了条件を決めて、小さく実装する。
3. ビルドと対象機能の操作を確認し、結果を進捗記録へ残す。
4. ブランチからPull Requestを作り、別の人のレビュー後に統合する。

文書内のマップ画像は同じ `docs/` フォルダにあります。文書の詳細な履歴・固定マップ・検証チェックリストは各正式文書を参照してください。
