## ゲームの基本ルール

### 遊び方

- **チュートリアル**：前進・旋回・探索マップ・鍵・ゴールを練習します。トラップはありません。
- **試練の迷宮**：固定マップを探索し、テスト用のトラップと鍵を経てゴールします。
- **ランダムステージ**：seedから生成する迷宮です。剣を取り、敵と戦い、鍵を得てゴールします。
- 上フリックは1マス前進、左右フリックはその場で旋回、下フリックは180度反転です。
- 罠はA（T/F/H：状態変化）、B（U/R/P：ワープ）、C（D/N：運命）の3グループを実装しています。ランダムステージはグループAだけから2マスを抽選します。
- 探索マップには到達・確認した場所だけを表示します。未探索の通路や特殊マスを先に見せません。

### ランダムステージと戦闘

- 17×17マスをseedから生成し、同じseedでは同じマップ・テーマ・配置を再現します。
- 進行の基本は **S（開始）→ W（剣）→ 敵 → K（鍵）→ 敵 → G（ゴール）** です。敵は2体で、少なくとも1体はガーゴイルです。
- 剣で攻撃力が上がります。スライムとスケルトンは剣なしでも倒せます。ガーゴイルには剣なしの攻撃が通りません。
- スケルトンは持ち時間、クリアタイム、HPに関わるアイテムを落とす場合があります。
- ランダムステージの罠は選択されたS-G最短経路外の異なる2位置へ置きます。各位置でグループA（T/F/H）から設定率に従って独立抽選するため、種類が重複する場合があります。同じseedなら位置と効果を再現します。グループB/Cは抽選対象外です。

### クリア・タイム・記録

- 試練の迷宮とランダムステージは鍵を取ってゴールするとクリアします。チュートリアルも鍵取得後にゴールします。
- クリア画面から次の迷宮、同じ迷宮への再挑戦、タイトル画面へ進めます。
- クリア画面には今回のタイム・最短タイム・名前入力・上位100件のランキングを表示する仕様です。タイマーは戦闘中も進み、ゴールで止まります。
- ゲームオーバーやギブアップはクリア記録にしません。チュートリアルもタイム記録の対象外です。

## 変更するときの標準手順

1. 対象の仕様・担当・現在の進捗を確認する。
2. Gitの作業ツリーとブランチを確認し、バックアップを取る。
3. 仕様変更なら、先にチームで合意して仕様書を更新する。
4. 作業ブランチで担当範囲の最小限の変更を行う。既存コメントは意図なく削除しない。
5. 差分を確認し、ビルドと回帰確認を行う。
6. Simulator・実機で対象機能を確認し、別担当者のレビューを受ける。
7. 進捗記録を更新し、Pull Requestで統合する。`main`へ直接変更しない。
